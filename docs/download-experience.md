# Catalog downloads

Catalog Image/PDF links open one full-screen download lightbox on the current page. No route, query, hash, browser history entry or extra tab is created. A viewport-sized native dialog dims the existing page and presents a separate white download screen. The background scroll position is locked and restored when it closes. It uses the shared colored action icons and blue download button.

The user can check the preview, format, dimensions, file size and license, switch formats, then save the original. Closing restores focus to the entry control. Escape, the close buttons and a backdrop click close the lightbox. Native dialog semantics keep keyboard focus inside it. Changing artwork, changing format, closing, or replacing the source cards cancels the previous operation. Metadata failures offer a retry; file failures leave the download action available for another attempt.

The existing versioned search card chunks now include the small download record: original dimensions, print information, exact byte counts and SHA-256 checksums. Artwork detail pages embed that record, so opening their lightbox needs no metadata request. Catalog cards resolve only the selected artwork's chunk, not the full catalog. The schema version changed so previous cached chunks cannot masquerade as current file details. A replaced deployment's missing chunks cause a fresh manifest lookup. Metadata comes only from approved, published catalog records.

The downloader keeps its origin allowlist, CORS fetch, time and size bounds, MIME/signature checks, exact byte count and SHA-256 verification before creating a local Blob download. Requests capture immutable file names and metadata, so switching formats cannot save the wrong file under a different name. The file request bypasses an opaque preview cache entry. Editor-generated exports retain their existing workflow.

Without JavaScript, links point directly to the original files with a download filename. Cross-origin browser behavior may open the file instead; the browser's Save control remains available. The obsolete download HTML route and its stylesheet have been removed. The Pages redirect rule permanently sends legacy `/download/{id}/` links to the corresponding `/art/{id}/` page; no separate download HTML documents are generated. This hosting redirect applies on publication, not in Astro's development router.

Guides and teacher instructions describe the lightbox workflow. The old standalone-page screenshot is no longer presented as the current interface. This change makes no advertising requests and activates no ad provider. Local cache cleanup must preserve Favorites, boards and editable projects. Production cache changes require the owner's explicit publication approval.
