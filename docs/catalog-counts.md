# Automatic catalog counts

Public totals are computed once from the catalog by `src/lib/catalog-statistics.ts`. `publishedArt` includes only records with `published` and `indexable` enabled. Registered topics count only when they contain published artwork. Collections count only when they contain an available topic; artwork in overlapping collections is counted once in the site total and once within each applicable collection.

`CatalogCount.astro` renders the full, formatted build-time value and marks its scope: all artwork, available subjects/collections, a particular topic or collection, or the print library. Homepage cards, About, Categories, collection/topic pages, Teachers, New, Search's library notice and Studio use this component. The print-library rule matches `blackAndWhiteArt`: published originals that pass the automatic monochrome asset audit, including neutral shaded drawings and silhouettes. Colored layered artwork does not qualify just because Studio can convert it. See `black-and-white.md`. Search results, directory filters, Favorites and the editor's loaded library report their actual result sets rather than being overwritten by a global total.

Every normal static build emits a small `/catalog-stats.json` containing only aggregate counts and a version. It has `Cache-Control: no-store` in both its response and the shared hosting headers. No catalog images or full artwork metadata are fetched for counters. Adding, withdrawing or regrouping published records changes the counts automatically, with no separate update command or manually maintained counter file.

Pages with counters request the current endpoint on load. Visible pages recheck every 30 seconds and on focus, tab return or back/forward restoration, with overlapping requests suppressed and an eight-second timeout. A changed version updates all marked counts together. Count-based directory sorting is then refreshed without clearing filters. Hidden tabs do not poll. A failed request leaves the complete build-time/last successful values in place; offline and JavaScript-disabled pages keep the build-time counts.

`CollectionCountCopy.astro` and `resolveCollectionCountCopy` keep introductory text and metadata consistent too. Existing leading quantity claims such as “Explore 50 cat clipart designs” are resolved against the topic's current count. New copy can use `{{artworkCount}}` explicitly. Counts of depicted objects, dimensions, page sizes, numbered instructions and style subsets are not replaced with library totals.

The site is static. New counts become available when the reviewed catalog/topic changes are included in the normal site build and publication. Uploading an unregistered file to storage does not make it published artwork. Local development recalculates counts from the edited catalog through Astro's normal reload; production changes still require the owner's explicit publication authorization.
